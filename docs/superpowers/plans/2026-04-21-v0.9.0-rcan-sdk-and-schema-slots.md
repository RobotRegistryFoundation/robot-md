> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the `rcan-py>=3.0` SDK dependency and `compliance.annex_iii_basis` enum to the ROBOT.md schema. Spec-strict, additive, no enforcement.

**Architecture:** rcan-py 3.0 (now on PyPI) unlocks SDK primitives (`rcan.crypto` signing, `rcan.manifest.from_manifest`, version constants) for later sub-releases. One schema field is added: `compliance.annex_iii_basis` with the 10 Annex III use-case values exactly as rcan-spec §22 defines. No signing, no FRIA gating, no §23/§24/§25/§26 schema slots (those concepts describe external artifacts per the spec; CLI emission commands handle them in v0.9.3-v0.9.5).

**Tech Stack:** Python 3.10-3.13, jsonschema (existing), pyyaml (existing), rcan 3.0 (new dep), ruff, pytest.

**Spec:** `docs/superpowers/specs/2026-04-21-v0.9-rcan-3-compliance-design.md` (as revised 2026-04-21 pm, 2nd). Do not widen.

**Budget:** ~30-45 minutes.

**Out of scope (deferred to later sub-releases):**
- Signing / ML-DSA / Ed25519 hybrid (v0.9.1)
- SDK second-pass validator (dropped — rcan-py has no `validate_manifest` API)
- FRIA enforcement when `annex_iii_basis` is set (v0.9.2)
- §23 Safety Benchmarks — CLI emission command, not a ROBOT.md field (v0.9.3)
- §24 IFU, §25 PMM — CLI emission/hooks (v0.9.4)
- §26 EU Register — submission pipeline (v0.9.5)
- RCN/RMN/RHN registry IDs (v0.9.6)

- [ ] **Step 1: Write failing tests**

Create `cli/tests/unit/test_schema_annex_iii_basis.py`:

```python
"""v0.9.0 — compliance.annex_iii_basis slot.

Per rcan-spec §22, a robot declares which Annex III use case basis it falls
under (if any). Enum of 10 values; optional in v0.9.0. FRIA gating (requiring
fria_ref when annex_iii_basis is set) arrives in v0.9.2.
"""

from __future__ import annotations

from robot_md.validate import validate_manifest_dict


ANNEX_III_BASES = (
    "safety_component",
    "biometric",
    "critical_infrastructure",
    "education",
    "employment",
    "essential_services",
    "law_enforcement",
    "migration",
    "administration_of_justice",
    "general_purpose_ai",
)


def _base() -> dict:
    """Minimal manifest shell that passes v1 schema."""
    return {
        "rcan_version": "3.0",
        "metadata": {
            "name": "t",
            "manufacturer": "acme",
            "model": "t1",
            "firmware_version": "0.0.0",
        },
        "physics": {"dof": 0, "joints": []},
        "drivers": [],
        "safety": {},
        "compliance": {},
    }


def test_annex_iii_basis_is_optional():
    m = _base()
    errors, _ = validate_manifest_dict(m)
    assert errors == [], errors


def test_annex_iii_basis_accepts_each_spec_value():
    for v in ANNEX_III_BASES:
        m = _base()
        m["compliance"]["annex_iii_basis"] = v
        errors, _ = validate_manifest_dict(m)
        assert errors == [], f"{v}: {errors}"


def test_annex_iii_basis_rejects_unknown_value():
    m = _base()
    m["compliance"]["annex_iii_basis"] = "bogus_category"
    errors, _ = validate_manifest_dict(m)
    assert any(
        "annex_iii_basis" in e or "enum" in e.lower() for e in errors
    ), errors
```

NOTE: If `validate_manifest_dict` doesn't exist under that name, grep `cli/src/robot_md/validate.py` for the public function. Candidates: `validate_manifest`, `validate_dict`, `validate`. **Do NOT change validate.py itself** — unpack the return value to match its actual shape. If it returns only `list[str]` errors, do `errors = validate_manifest_dict(m); _ = []` instead of tuple-unpacking.
