# robot-md v0.9.0 Implementation Plan (revised 2026-04-21 pm)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the `rcan-py>=3.0` SDK dependency and scaffold §22-§26 RCAN 3.0 schema slots, all additive. After this release, ROBOT.md manifests can declare EU AI Act compliance fields, but no field is required yet and no signing is performed.

**Architecture:** A dependency bump (`rcan>=3.0,<4.0`, now live on PyPI as of 2026-04-21) unlocks SDK primitives (crypto, `from_manifest`, version constants) for later sub-releases. Five new optional objects join `schema/v1/robot.schema.json` (one enum on `metadata`, four objects under `compliance`). robot-md's jsonschema validation remains the single validator for ROBOT.md — rcan-py is a *library*, not a co-validator. No signing, no enforcement, no tightening of existing fields — those are v0.9.1-v0.9.4.

**Tech Stack:** Python 3.10-3.13, jsonschema (existing), pyyaml (existing), rcan 3.0 (new dep), ruff, pytest.

**Spec:** `docs/superpowers/specs/2026-04-21-v0.9-rcan-3-compliance-design.md` "v0.9.0 — detailed scope" section (as revised 2026-04-21 pm). Do not widen.

**Budget:** One focused session (~45-60 minutes).

**Out of scope (deferred to later sub-releases — do NOT leak in):**
- Signing / ML-DSA / Ed25519 hybrid (v0.9.1)
- SDK second-pass validator (dropped entirely — rcan-py has no `validate_manifest` API; ROBOT.md validation is robot-md's jsonschema alone)
- FRIA enforcement / Annex-III gating logic (v0.9.2)
- §23/§24/§25/§26 internal sub-schema depth (v0.9.3 — v0.9.0 only adds permissive `"type": "object"` shells)
- RURI construction (v0.9.1)
- RCN/RMN/RHN registry IDs (v0.9.4)

**What was already established (you don't need to re-do these):**
- rcan-py 3.0.0 is live on PyPI (published 2026-04-21 from `continuonai/rcan-py@v3.0.0`).
- `requires-python = ">=3.10"` — CI matrix stays 3.10/3.11/3.12/3.13.
- SDK API shape: `rcan.crypto.sign_hybrid/verify_hybrid/sign_ml_dsa`, `rcan.manifest.from_manifest(path)`, `rcan.version.SPEC_VERSION == "3.0"`. No `validate_manifest(fm)` exists or is needed.
- Schema `rcan_version` already pinned to `^3\.[0-9]+(\.[0-9]+)?$` in commit `cf25f6a`.

Adds an optional enum field to classify the robot under EU AI Act Annex-III.
v0.9.0 adds only the slot; gating logic arrives in v0.9.2.
"""

from __future__ import annotations


from robot_md.validate import validate_manifest_dict


def _base() -> dict:
    """Minimal manifest shell that passes v1 schema (shared across tests)."""
    return {
        "rcan_version": "3.0",
        "metadata": {
            "name": "t",
            "manufacturer": "acme",
            "model": "t1",
            "firmware_version": "0.0.0",
        },
        "physics": {"dof": 0, "joints": []},
        "drivers": [],
        "safety": {},
    }


def test_annex_iii_classification_is_optional():
    m = _base()
    errors, _ = validate_manifest_dict(m)
    assert errors == [], errors


def test_annex_iii_classification_accepts_enum_values():
    for v in ("not_classified", "high_risk", "limited_risk", "minimal_risk"):
        m = _base()

        errors, _ = validate_manifest_dict(m)

def test_annex_iii_classification_rejects_unknown_value():
    m = _base()
    m["metadata"]["annex_iii_classification"] = "bogus"
    errors, _ = validate_manifest_dict(m)
    assert any("annex_iii_classification" in e or "enum" in e.lower() for e in errors), errors
