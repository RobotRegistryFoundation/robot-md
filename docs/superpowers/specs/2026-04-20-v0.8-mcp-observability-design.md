# robot-md v0.8 — MCP Observability Design

> **Status:** Design approved 2026-04-20. Sibling of `2026-04-20-v0.7-hardening-design.md` (which shipped) and `2026-04-20-v0.8-v0.9-roadmap.md` (bucket **E**).
>
> **Scope:** Three additive features on top of the existing `robot-md-mcp` server:
> 1. `recent_invocations` + `recent_errors` MCP resources (backed by a per-context `InvocationLog`).
> 2. Structured preconditions — `suggested_fix` exposed on every precondition failure.
> 3. Streaming progress for the `discover` tool (MCP `Context.report_progress` + `discover.step.*` JSONL events).
>
> **Breaking change:** the `execute_capability` error shape for precondition failures changes. `error.failed: list[str]` is removed and replaced by `error.preconditions: list[dict]`. Downstream parsers must read the new field.

---

## Background

`robot-md-mcp` has been shipping since v0.3 and today exposes tools (`render`, `validate`, `estop`, `estop_clear`, `execute_capability`, `execute_task`, `vision_find`, `record_skill`, `discover`) and three resources (`learned_skills`, `calibration_status`, `poses`). A dashboard `EventPublisher` writes `tool.call` / `tool.result` / `estop.*` / `frame` events to `~/.robot-md/events.jsonl` in a separate path from the MCP client.

The v0.7 hardware bring-up surfaced two recurring agent UX gaps:

- **"Why did my last pick fail?"** requires the agent to shell out and read server logs. There is no MCP-native way to ask.
- **Precondition failures** return an opaque `list[str]` like `"hand-eye extrinsic missing (run `robot-md calibrate --hand-eye`)"`. The remediation hint is embedded in prose; an agent cannot reliably parse it to act.
- **`discover`** is declarative and can take multiple seconds (arm motion + image capture). It blocks synchronously with no intermediate feedback.

v0.8 E addresses all three with the smallest plumbing that survives into v0.9.

## Goals

1. An MCP client can read a resource on the robot-md server and see the last 100 capability invocations (call, args, status, reason, structured hint, request_id) without leaving the MCP surface.
2. When a precondition fails, `execute_capability` returns a structured per-precondition record with `kind`, `name`, `message`, and `suggested_fix` — every branch of the evaluator fills `suggested_fix` with an actionable command or declares `null` if unfixable.
3. `discover` reports progress at every step — MCP progress notifications to the client, `discover.step.*` events on the JSONL dashboard substrate.
4. Breaking changes are contained, tested, and called out in CHANGELOG.

## Non-goals

- Log rotation / retention of `~/.robot-md/events.jsonl` (today it grows unbounded — still does).
- Redaction of args (single-user local-rig context; args returned verbatim).
- Query-parameterised resource reads (no `?limit=`, `?since=`).
- New capabilities, drivers, calibration work.

## Architecture

Three additions, all layered on existing infrastructure:

```
┌─────────────────────────── McpContext ────────────────────────────┐
│                                                                    │
│  EventPublisher ──▶ events.jsonl                                   │
│         │                                                          │
│         └──▶ [manifest_path-stamping wrapper]                      │
│                    │                                               │
│                    ├──▶ fan-out hook ──▶ InvocationLog (ring 100)  │
│                    │                         │                     │
│                    │                         ▼                     │
│                    │                  recent_invocations resource  │
│                    │                  recent_errors resource       │
│                    │                                               │
│                    ▼                                               │
│         dashboard consumer (unchanged)                             │
│                                                                    │
│  boot: InvocationLog.backfill_from_jsonl(events.jsonl, manifest)   │
│                                                                    │
└────────────────────────────────────────────────────────────────────┘
```

**Unifying primitive:** `InvocationLog` — a per-`McpContext` in-memory ring of `InvocationRecord` objects, maxlen 100. Populated live by the publisher hook; backfilled at boot from `events.jsonl`. Two thin resource functions read snapshots from it.

**Preconditions:** the `evaluate(...)` function's second return element becomes `list[PreconditionFailure]` instead of `list[str]`. Every `_check_one` branch constructs a `PreconditionFailure` with its own `suggested_fix`. `execute_capability_tool` passes the structured list into the error payload under `preconditions`.

**Streaming:** `discover` accepts an optional FastMCP `Context` parameter; after each step it calls `ctx.report_progress(i, total, step_name)` and fires a `discover.step.begin` / `discover.step.end` event on the publisher.

## Components

### New files

#### `cli/src/robot_md/mcp/invocation_record.py`

```python
from dataclasses import dataclass, field
from typing import Any

@dataclass(frozen=True)
class InvocationRecord:
    timestamp: float
    tool: str                     # "execute_capability" | "discover" | "execute_task" | ...
    capability: str | None        # set for execute_capability; None otherwise
    args: dict[str, Any]
    status: str                   # "ok" | "error" | "blocked" | "no_backend" | ...
    reason: str | None            # from error.reason (or None on success)
    suggested_fix: str | None     # only when reason == "precondition" (joined from per-prec hints)
    request_id: str
    manifest_path: str
    preconditions: list[dict] = field(default_factory=list)  # populated when reason == "precondition"
```

Construction helper: `InvocationRecord.from_event_pair(call_evt: dict, result_evt: dict, manifest_path: str) -> InvocationRecord`.

#### `cli/src/robot_md/mcp/invocation_log.py`

```python
import threading
from collections import deque
from pathlib import Path
from robot_md.mcp.invocation_record import InvocationRecord

class InvocationLog:
    def __init__(self, maxlen: int = 100) -> None:
        self._buf: deque[InvocationRecord] = deque(maxlen=maxlen)
        self._lock = threading.Lock()

    def append(self, record: InvocationRecord) -> None:
        with self._lock:
            self._buf.append(record)

    def snapshot(self) -> list[dict]:
        """Newest-first, ≤maxlen entries, as JSON-serializable dicts."""
        with self._lock:
            return [_as_dict(r) for r in reversed(self._buf)]

    def snapshot_errors(self) -> list[dict]:
        """snapshot() filtered to status != 'ok'."""
        return [r for r in self.snapshot() if r["status"] != "ok"]

    def backfill_from_jsonl(
        self,
        path: Path,
        manifest_path: str,
        n: int = 100,
    ) -> None:
        """Reverse-scan path, pair tool.call/tool.result by request_id, filter
        by manifest_path, append oldest-first into the ring. Never raises."""
```

### Modified files

#### `cli/src/robot_md/preconditions.py`

Add `PreconditionFailure` dataclass; change evaluator return type.

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class PreconditionFailure:
    kind: str                     # matches the precondition's kind string
    name: str | None              # the precondition's name field (e.g., pose name)
    message: str                  # human-readable description of what's missing
    suggested_fix: str | None     # actionable command, or None if unfixable

def evaluate(
    contract: CapabilityContract,
    spec: Any,
    *,
    backend_resolved: bool,
) -> tuple[bool, list[PreconditionFailure]]: ...
```

Each `_check_one` branch returns a `PreconditionFailure` instead of a string. For the existing kinds:

| kind | message | suggested_fix |
|---|---|---|
| `backend_resolved` | `"no backend resolved for any driver"` | `"check ROBOT.md drivers[] and connected hardware"` |
| `pose_taught` | `"pose '<name>' not taught"` | `"robot-md pose teach <name>"` |
| `extrinsic_present` | `"hand-eye extrinsic missing"` | `"robot-md calibrate --hand-eye"` |
| `ik_provider_set` | `"physics.solver.ik_provider not declared"` | `"set physics.solver.ik_provider in ROBOT.md"` |
| `workspace_declared` | `"physics.workspace not declared"` | `"declare physics.workspace in ROBOT.md"` |
| `learned_skill_ok` (not recorded) | `"learned skill '<id>' not recorded"` | `"robot-md record-skill <id>"` |
| `learned_skill_ok` (status != ok) | `"learned skill '<id>' status=<status>"` | `null` (requires diagnosing the skill; no single command) |
| unknown kind | `"unknown precondition kind '<kind>'"` | `null` |

#### `cli/src/robot_md/mcp/tools/execute_capability.py`

Error payload for precondition blocks changes:

```python
# OLD
result = {
    "status": "blocked",
    "error": {"reason": "precondition", "failed": failed},  # list[str]
}

# NEW
result = {
    "status": "blocked",
    "error": {
        "reason": "precondition",
        "preconditions": [asdict(f) for f in failed],  # list[dict]
    },
}
```

After `_publish_result(ctx, ...)`, the invocation is appended to the log via the publisher fan-out hook (not a direct call — fan-out is centralised at the `ctx.publisher.publish` layer so every path is covered uniformly).

#### `cli/src/robot_md/mcp/tools/discover.py`

Accept an optional `mcp_ctx: Context | None = None` (FastMCP injects it); each step emits progress:

```python
def discover_tool(
    ctx: Any,
    *,
    steps: list[dict],
    mcp_ctx: Any | None = None,
) -> dict:
    total = len(steps)
    results: dict[str, Any] = {}
    frame = None
    for i, step in enumerate(steps):
        if not isinstance(step, dict) or len(step) != 1:
            continue
        (name, payload) = next(iter(step.items()))
        _publish_step(ctx, "begin", name, i, total)
        if mcp_ctx is not None:
            try:
                mcp_ctx.report_progress(i, total, name)
            except Exception:
                pass  # never fail a step because progress reporting failed
        # ... existing step dispatch ...
        _publish_step(ctx, "end", name, i, total, status=results[name].get("status"))
    return {"status": "ok", "results": results}
```

`_publish_step` fires `discover.step.begin` / `discover.step.end` with `{name, i, total, status?}`.

#### `cli/src/robot_md/mcp/server.py`

```python
@server.tool()
def discover(steps: list[dict], mcp_ctx: Context = None) -> dict:
```


#### `cli/src/robot_md/mcp/context.py`

`McpContext` dataclass gains `invocation_log: InvocationLog`. `load_context()`:

1. Constructs `InvocationLog(maxlen=100)`.
2. Calls `invocation_log.backfill_from_jsonl(events_dir / "events.jsonl", str(manifest_path), n=100)`.
3. Wraps `publisher.publish` with a manifest-stamping wrapper that (a) stamps `manifest_path` into every event payload, (b) fans out paired `tool.call` / `tool.result` events to `InvocationLog` (keyed by `request_id`, with a 60s pending-call TTL map for unpaired calls).

The pending-call map lives on `McpContext` itself:

```python
@dataclass
class McpContext:
    ...
    invocation_log: InvocationLog = field(default_factory=lambda: InvocationLog(maxlen=100))
    _pending_calls: dict[str, dict] = field(default_factory=dict)
    _pending_lock: threading.Lock = field(default_factory=threading.Lock)
```

#### `cli/src/robot_md/mcp/resources.py`

Add `recent_invocations(ctx)` and `recent_errors(ctx)` — simple pass-throughs to `ctx.invocation_log.snapshot()` and `ctx.invocation_log.snapshot_errors()`. Keep the pure style (no I/O).

#### `cli/src/robot_md/dashboard/events.py`

**No change.** Manifest-path stamping is applied at the `McpContext.publisher.publish` wrapper tier, not inside `EventPublisher`, to keep that module general.

## Data flow

### Invocation logging (live)

```
MCP client ──execute_capability(cap, args)──▶ execute_capability_tool
                                                    │
                                    publish tool.call {manifest_path stamped, request_id}
                                                    │
                                       [precondition / estop / gate / exec]
                                                    │
                                    publish tool.result {manifest_path stamped, status, error}
                                                    │
               manifest-stamp wrapper: pair call+result by request_id
                                                    │
               ctx.invocation_log.append(InvocationRecord.from_event_pair(…))
                                                    │
                                                 return
```

Only **completed** invocations enter the log. A `tool.call` without a matching `tool.result` stays in `_pending_calls` with its insertion time; entries older than 60s are discarded on next sweep.

### Boot-time backfill

```
load_context(manifest):
  publisher = EventPublisher(~/.robot-md/events.jsonl)
  invocation_log = InvocationLog(maxlen=100)
  invocation_log.backfill_from_jsonl(
      path=~/.robot-md/events.jsonl,
      manifest_path=str(manifest),
      n=100,
  )
  # reverse-scan, pair by request_id, filter events whose manifest_path matches,
  # append oldest-first so the deque ends up newest-at-right.
```

The scan stops once 100 paired records for this manifest are collected, or the file is exhausted. `tool.call` without matching `tool.result` in the file is dropped (same rule as runtime).

### Resource reads

```
MCP client ──read recent_invocations──▶ resources.recent_invocations(ctx)
                                             │
                              return ctx.invocation_log.snapshot()
                                             │
                              list[dict], newest first, ≤100 entries
```

`recent_errors` is identical except it calls `snapshot_errors()`.

### Discover streaming

```
MCP client ──discover(steps=[...], progressToken=X)──▶ discover tool binding
                             │                                  │
                             │                 discover_tool(ctx, steps, mcp_ctx)
                             │                                  │
                             │           for i, step in enumerate(steps):
                             │             publisher.publish("discover.step.begin", {...})
                             │             mcp_ctx.report_progress(i, total, step_name)
                             │             <run step>
                             │             publisher.publish("discover.step.end", {..., status})
                             │                                  │
                             ◀─── progress notifications (one per step, async)
                             ◀─── final result (same shape as v0.7)
```

### Precondition structured return

```
execute_capability ──▶ evaluate(contract, spec, backend_resolved=True)
                              │
               returns (False, [PreconditionFailure(kind='extrinsic_present', …), …])
                              │
    result = {
      "status": "blocked",
      "error": {
        "reason": "precondition",
        "preconditions": [asdict(p) for p in failures],
      },
    }
```

## Error handling & edge cases

| Condition | Behavior |
|---|---|
| `events.jsonl` missing at boot | `backfill_from_jsonl` logs warning, returns empty ring, server continues |
| `events.jsonl` has malformed line | Skip line, continue scan, log warning with line count |
| `events.jsonl` truncated mid-line | Skip partial line, continue |
| Backfill file locked by concurrent writer | Open read-only; partial results accepted; swallow `OSError` |
| `tool.call` with no matching `tool.result` at runtime | Kept in `_pending_calls` for 60s then dropped |
| `tool.call` with no matching `tool.result` during backfill | Dropped |
| Unknown precondition `kind` | Returns `PreconditionFailure(kind=<kind>, message="unknown precondition kind '<kind>'", suggested_fix=None)` |
| `discover` run outside FastMCP (tests, direct call) | `mcp_ctx=None`; `report_progress` skipped; events.jsonl events still fire |
| `report_progress()` raises | Swallow; continue step execution. One failed progress notification must not abort a discover |
| Resource read during concurrent tool execution | Snapshot under lock; microsecond-scale copy; never blocks execute |
| Empty ring | Both resources return `[]`; clients must handle |
| Empty errors | `recent_errors` returns `[]`; clients must handle |

**Breaking change migration.**

- `execute_capability` error shape for `reason: "precondition"` switches from `{reason, failed: list[str]}` to `{reason, preconditions: list[dict]}`.
- No compat field is shipped. The CHANGELOG calls it out under v0.8.0 Breaking.
- Internal updates required in the same release: `test_mcp_tools_execute_capability.py`, any CLI error-formatter code (search repo for `error\[\"failed\"\]` and `error.get("failed")`).
- External MCP clients parsing the old field will see the field missing. They must read `error["preconditions"]` and render `preconditions[*].message` + `preconditions[*].suggested_fix`.

## Testing

### Unit tests (fast, no hardware, no MCP runtime)

- **`test_invocation_log.py`** — ring bounds (101st append evicts oldest), thread-safety under concurrent append+snapshot, `snapshot()` newest-first ordering, `snapshot_errors()` filter correctness, `backfill_from_jsonl` happy path + missing-file + malformed-line + manifest-path filter + truncated-line.
- **`test_invocation_record.py`** — `from_event_pair()` field mapping for success, `reason='precondition'` (pulls `preconditions` into the record), `reason='estop_set'`, `reason='busy'`, `reason='hitl_gate'`, raw exec error status.
- **`test_preconditions_structured.py`** — every `kind` branch returns a `PreconditionFailure` with the expected `{kind, name, message, suggested_fix}`. Unknown kind returns unfixable failure. Multiple failing preconditions return in declared order.
- **`test_mcp_resources_invocations.py`** — `recent_invocations(ctx)` returns ring snapshot; `recent_errors(ctx)` filters correctly. Mock `McpContext` with a hand-populated `InvocationLog`.
- **`test_mcp_tools_execute_capability.py`** (modified) — precondition-fail returns `{reason: "precondition", preconditions: [...]}` not `{failed: [...]}`. Invocation appears in ring with matching `request_id`.
- **`test_mcp_discover_progress.py`** — stub `Context` captures `report_progress` calls; verify one call per step with `(i, total, step_name)`. Verify publisher received `discover.step.begin`/`discover.step.end` per step.
- **`test_events_manifest_stamp.py`** — the manifest-stamping wrapper adds `manifest_path` to every event; existing fields preserved.

### Integration tests

- **`test_mcp_server_backfill.py`** (new) — start server A with manifest M, invoke a capability that fails preconditions, stop A, start server B with the same M, read `recent_errors` resource, assert the prior failure is present.
- **`test_mcp_discover_streaming.py`** (new) — run `discover` through FastMCP stdio with a client that captures progress notifications; verify one notification per step. Skip if the test backend lacks a stub `Context`.
- **`test_mcp_server_lifecycle.py`** (modified) — add assertion: after a successful capability run, `recent_invocations` resource returns a record for it.

## CHANGELOG entry (v0.8.0)

```
## [0.8.0] — <release date>

### Added
- MCP resource `robot-md://<robot>/recent_invocations` — last 100 capability
  invocations with timestamp, tool, args, status, reason, request_id,
  manifest_path.
- MCP resource `robot-md://<robot>/recent_errors` — same as recent_invocations
  filtered to status != "ok".
- `suggested_fix` field on every precondition failure returned by
  `execute_capability`. Every precondition kind now emits a structured record
  with actionable remediation text (or null if unfixable).
- `discover` tool now emits MCP progress notifications per step
  (`Context.report_progress`) and publishes `discover.step.begin` /
  `discover.step.end` events on the dashboard stream.

### Changed (breaking)
- `execute_capability` error shape for `reason: "precondition"` changes from
  `{reason, failed: list[str]}` to `{reason, preconditions: list[dict]}`.
  Each entry: `{kind, name, message, suggested_fix}`. MCP clients parsing the
  old `failed` field must read `preconditions` and render
  `preconditions[*].message` and `preconditions[*].suggested_fix`.
- `robot_md.preconditions.evaluate(...)` return type changes from
  `(bool, list[str])` to `(bool, list[PreconditionFailure])`. Direct callers
  of this function need updating; the MCP error payload surface is the more
  common consumer.

### Internal
- New `robot_md.mcp.invocation_log.InvocationLog` (per-context ring buffer,
  maxlen 100, backfilled from events.jsonl at boot).
- `EventPublisher.publish` is wrapped at the `McpContext` layer to stamp
  `manifest_path` on every event and fan out paired `tool.call`/`tool.result`
  events into the invocation log.
```

## Implementation order

1. **`InvocationRecord` + `InvocationLog`** (no dependencies; unit-testable in isolation).
2. **Manifest-path stamping wrapper + fan-out to `InvocationLog`** in `McpContext`.
3. **`recent_invocations` + `recent_errors` resources** + register in `server.py`.
4. **Precondition structured return** — rewrite `preconditions.py`, update `execute_capability_tool`, update `test_preconditions.py` and `test_mcp_tools_execute_capability.py`.
5. **`discover` streaming** — add `mcp_ctx` param, progress + events.jsonl emissions.
6. **Integration tests** — backfill, streaming, lifecycle.
7. **CHANGELOG + version bump to 0.8.0** (breaking) + release.

Each step is commit-sized; one commit per step, TDD. Post-step, the suite should be green.
