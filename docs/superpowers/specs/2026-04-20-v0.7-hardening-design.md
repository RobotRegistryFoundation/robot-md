# robot-md v0.7 — Hardening Release Design

> **Status:** Approved 2026-04-20. Ready for implementation plan.
>
> **Scope:** A (hardware correctness & recovery) + B (perception polish) + D (calibration UX) from the v0.7 gap survey. C/E/F go to v0.8; bimanual/LfD/SLAM/mobile-base go to v0.9. See `2026-04-20-v0.8-v0.9-roadmap.md` for the sibling doc.
>
> **Predecessor:** v0.6.3 (shipped 2026-04-20). First real SO-ARM101 + OAK-D bring-up exposed five motion-layer bugs (all fixed in v0.6.3) and surfaced architectural gaps — this design addresses the gaps.

---

## Summary

v0.7 is a **hardening release**. Three themes stacked on the same spine:

1. **Ground-truth geometry.** Depth and extrinsic become first-class. HSV detectors gain automatic depth filtering from the declared workspace. Camera-to-arm calibration moves to gripper-silhouette matching — no printed marker, no hand-measured `--marker-pos`.
2. **Defensive motion.** The arm never needs physical recovery from a software-preventable state. Pre-flight envelope analysis rejects trajectories likely to trip STS3215 latch; motion-layer watchdog detects latch the moment it happens and contains damage; doctor surfaces the condition post-hoc.
3. **Preset-scoring correctness.** `init` picks the right preset every time — `so_arm101` vs `so_arm101_leader` stops being a coin flip.

Behavior changes are minor; backward compatibility is preserved at the manifest and data-format level. The user-visible wins are: calibration works with zero print/measure steps, `white_bowl`-at-8m-wall false positives disappear, and servo latch becomes a recoverable, diagnosable condition instead of a "why did the arm die?" mystery.

## Architecture

The v0.7 changes land on the existing v0.6.3 codebase as a mix of rewrites, modifications, and small new modules. No large-scale refactor.

### Module-level shape

| Module | Status | Notes |
|---|---|---|
| `robot_md.extrinsic` | unchanged | 6-vec↔4x4 math; consumers shift. |
| `robot_md.hand_eye` → `robot_md.calibrate_extrinsic` | **renamed + rewritten** | ArUco sweep removed; replaced by depth-silhouette sweep. |
| `robot_md.gripper_silhouette` | **new** | Renders expected gripper-tip point cloud at a given joint config from `physics.solver.gripper` + DH; matches against observed depth cloud; returns camera-frame centroid. |
| `robot_md.detectors.hsv` | modified | Grows optional depth filter; workspace-bounds default from parser. |
| `robot_md.detectors.depth` | **new, optional** | Depth-cluster detector for non-color targets (primary use case: `white_bowl`). |
| `robot_md.kinematics` | modified | Adds `analyze_envelope()` for pre-flight risk check. Existing joint-limit enforcement preserved. |
| `robot_md.backends.feetech_depthai.motion` | modified | Adds `verify_alive()` post-motion watchdog. |
| `robot_md.backends.feetech_depthai.doctor` | **new helper** | Hardware-state checks (servo enumeration, camera stream alive). |
| `robot_md.init_phases.calibrate_extrinsic` | **new** | TTY-gated init phase; non-interactive skips. |
| `robot_md.init` (`match_score`, `pick_best`) | modified | Adds `count`-aware scoring + optional `negative_hints` to resolve ties. |
| `cli/__main__.py` | modified | `calibrate --hand-eye` → `calibrate --extrinsic`; deprecation alias kept through v0.7. |

### Preset schema deltas (additive, v0.6.x still validates)

- `match.drivers.count` — already declared on `so_arm101` preset but unused; wire into scoring.
- `match.negative_hints: [str]` — new optional; `so_arm101` declares `["leader"]` to disambiguate from `so_arm101_leader`.
- `physics.solver.gripper.silhouette_points: [[x,y,z], ...]` — new optional; points in tool frame defining observable gripper geometry. Defaults inferred from `tip_offset_mm` + jaw open/close steps when absent.
- `physics.solver.cameras[].extrinsic_residual_mm: float` — new optional; populated by successful calibration. Exposed via doctor for trend tracking.
- `physics.solver.cameras[].extrinsic_source` — new enum value: `gripper_silhouette_calibrated`. `hand_eye_calibrated` remains valid (still produced by the v0.7 deprecation alias, and still read by consumers that don't care about the source).

### HSV descriptor schema delta

- `ignore_workspace_bounds: bool` (default `false`) — opt-out for descriptors whose valid matches sit outside the declared workspace envelope (e.g., a docking fiducial on the room wall).

### Compat

- v0.6.3 manifests validate and load. Extrinsic calibrated with v0.6.x ArUco still works — `hand_eye_calibrated` stays a valid enum value, just no longer the default producer.
- HSV descriptors with no depth fields continue to work — the auto-workspace filter is the new default (behavior change documented in changelog).

## Components

### `gripper_silhouette.py` (new, ~150 LOC)

- `expected_points(preset, joint_cfg) -> np.ndarray[N,3]` — forward-kinematics the gripper tip and returns a small set of 3D points in base frame representing observable gripper geometry (tip + two jaw corners). Derived from `physics.solver.gripper.tip_offset_mm`; override via optional `silhouette_points` field.
- `find_in_depth(depth_frame, K, expected_points_in_cam, search_radius_mm=50) -> tuple[np.ndarray[3], float]` — projects expected points into camera frame, searches nearby depth pixels for matching cluster (euclidean DBSCAN within radius), returns refined 3D centroid + confidence score ∈ [0,1]. Fails fast if cluster too sparse (<5 points) or too dispersed (std >20mm).
- Pure function module. No IO, no hardware. Fully unit-testable with synthetic depth frames.

### `calibrate_extrinsic.py` (renamed from `hand_eye.py`, rewritten ~250 LOC)

- `plan_sweep(preset, workspace_bounds_mm, n_poses=6) -> list[dict[str, int]]` — generates N joint configurations that keep the gripper visible from the camera (FK each candidate, reject if tip outside workspace bounds or behind arm per `base_frame` orientation). Deterministic given a seed; exposed for testability.
- `capture_sample(bus, camera, pose) -> Sample` — moves to pose via `motion.replay`, waits for settle, captures depth frame + joint readback. `Sample` dataclass: `joints`, `tip_cam`, `tip_base`, `confidence`.
- `solve(samples, preset) -> tuple[extrinsic_6vec, residual_mm]` — for each sample: observed camera-frame tip from `gripper_silhouette.find_in_depth`, expected base-frame tip from FK. Solve `extrinsic @ tip_cam = tip_base` as overdetermined rigid-body registration (Kabsch/Horn). Returns extrinsic + mean residual. Degenerate inputs (collinear samples) raise `CalibrationError`.
- `run(manifest_path, bus, camera) -> CalibrationResult` — orchestrates the three. Writes extrinsic, `extrinsic_source: gripper_silhouette_calibrated`, and `extrinsic_residual_mm` back to the manifest.

### `detectors/hsv.py` (modified, +40 LOC)

- New optional args: `min_depth_mm`, `max_depth_mm`. If unset, derived from the parser's `physics.workspace.bounds_mm` projected into camera frame via current extrinsic.
- Mask is joint: color-mask AND depth-mask. Centroid comes from joint-mask.
- Backward compat: descriptors without depth fields continue to work — auto-derivation is the new default. To opt out, descriptor sets `ignore_workspace_bounds: true`.
- Edge case: if extrinsic is `preset_default` (uncalibrated), the projected workspace may be wildly wrong. Detector emits a structured warning alongside its result so the caller can surface it ("your extrinsic hasn't been calibrated; depth filter may exclude valid matches").

### `detectors/depth.py` (new, ~80 LOC)

- `params: {shape: bowl|cylinder|plane, min_diameter_mm, max_diameter_mm, z_range_mm}` — geometric descriptors for non-color targets.
- Depth-first cluster (DBSCAN on the point cloud within `z_range_mm`) → shape fit (RANSAC for plane, least-squares for bowl/cylinder) → accept/reject based on diameter bounds and fit residual.
- Primary target: `white_bowl`. Registered alongside HSV in the detector registry.

### `kinematics.analyze_envelope()` (modified, +60 LOC)

- `analyze_envelope(joint_cfg, duration_ms, load_grams=50) -> EnvelopeRisk` — checks each declared `limits_rad` is satisfied (today's behavior, preserved). Adds latch-risk heuristic: `wrist_flex` sustained >85% of envelope for >`duration_ms` with `load_grams` at gripper-tip moment arm, OR any joint within 5° of its limit. Returns `EnvelopeRisk(level: ok|latch_warning|out_of_limits, joint, angle, recommendation)`.
- Called from `trajectory.plan_pick`, `trajectory.plan_place`, and `_arm_home` in the backend.
- Hard-fails `out_of_limits` (existing behavior). Hard-fails `latch_warning` at plan time by default; `--force-envelope` CLI flag allows override for experimental use (not recommended; emits loud warning).

### `feetech_depthai.motion.verify_alive()` (modified, +40 LOC)

- `verify_alive(bus, expected_ids: set[str]) -> AliveReport` — post-motion, read positions and compare enumerated servo IDs against expected. Missing ID = latched (the only mode observed in hardware bring-up where a servo drops from the bus without error response).
- On detection: torques off *remaining* servos (safety — prevents cascading damage), returns `AliveReport(alive=False, missing=[ids])`.
- Wired into `_do_replay`, `_execute_pick_or_place` post-motion paths (replacing the removed `torque(False)` from v0.6.3's torque-hold fix — we still hold torque on success, but drop it cleanly on latch detection).

### `feetech_depthai.doctor` (new helper module, ~100 LOC)

- `hw_checks(spec, bus, camera) -> list[Check]` — enumerate servo bus, match count against preset's declared count. Stream one OAK-D frame, confirm both RGB and depth streams present.
- Hooked into `robot-md doctor` behind new `--hardware` flag (default `auto`: `true` when bus/camera detected, `false` in CI).

### `init.match_score` + `pick_best` (modified, +30 LOC)

- Use `match.drivers.count` — if scan finds bus with N servos and preset declares `count: N`, +5 bonus. Count mismatch is 0, not negative — mismatch could be valid during early setup (servo missing because it's unplugged during bench work).
- Use new `match.negative_hints: [str]` — each hit in any device label subtracts 5. `so_arm101` declares `negative_hints: ["leader"]`. `so_arm101_leader` leaves it unset.
- Expected scoring for the canonical SO-ARM101 follower rig (feetech + 6 servos, no "leader" in any label): `so_arm101=15`, `so_arm101_leader=10`. Resolved.

### `init_phases/calibrate_extrinsic.py` (new, ~100 LOC)

- Post-scan, post-write-manifest, pre-doctor phase in the init pipeline.
- Skips cleanly (`PhaseResult(status=skipped, reason=...)`) if: non-interactive, no camera detected, no actuatable bus, or `extrinsic_source != preset_default`.
- On TTY: prompts `"Calibrate camera-to-arm alignment now? The arm will move through 6 poses. [Y/n]"`. If yes, invokes `calibrate_extrinsic.run()`. Writes the result; reports residual_mm to the operator.
- If user declines: skips. Doctor subsequently warns about uncalibrated extrinsic (existing behavior).

### Bug fix: `test_metadata_overrides_persisted_to_manifest`

- Root cause per memory: `phase_register` drops `--manufacturer`/`--model` CLI overrides before write. Trace `write_manifest` → verify the frontmatter dict contains overrides → fix the dropping call site. Separate task, separate commit from the feature work.

## Data Flow

### Flow 1: `robot-md init` with extrinsic calibration (the new happy path)

```
1. autodetect.scan_system() → devices + cameras
2. init.pick_best() → so_arm101 (now wins cleanly over leader via negative_hints + count)
3. merge_preset_into_draft() → draft with preset_default extrinsic
4. phase_write_manifest() → ROBOT.md on disk
5. phase_auto_calibrate_ready() → physics.poses.ready via DH+IK (unchanged from v0.6.3)
6. phase_calibrate_extrinsic() (NEW):
     if non_interactive or no_camera or no_actuatable_bus: skip, exit
     prompt: "Calibrate camera-to-arm alignment now? [Y/n]"
     if no: skip, doctor will warn
     if yes:
         samples = []
         for pose in calibrate_extrinsic.plan_sweep(preset, workspace_bounds, n=6):
             motion.replay([Waypoint(joints=pose)])   # moves arm
             motion.verify_alive()                     # watchdog
             depth, K = camera.capture()
             tip_cam, confidence = gripper_silhouette.find_in_depth(depth, K, ...)
             tip_base = kinematics.fk(pose)
             samples.append(Sample(tip_cam, tip_base, confidence))
         extrinsic, residual = calibrate_extrinsic.solve(samples)
         if residual > 15mm: prompt user — continue, redo, or abort
         write_extrinsic(manifest, extrinsic, source="gripper_silhouette_calibrated")
         report: "Calibrated — mean residual 4.2 mm"
7. phase_doctor() → all checks green
```

### Flow 2: `arm.pick("red_lego")` with depth-aware detector + pre-flight

```
evaluate_preconditions() → extrinsic_present, ik_provider_set, workspace_declared, backend_resolved
  ↓ (all pass)
perception.vision_find("red_lego"):
  descriptor = find_descriptor("red_lego")
  if descriptor.depth bounds unset and not ignore_workspace_bounds:
      bounds = project(workspace_bounds, extrinsic)
  elif descriptor has bounds: bounds = descriptor's own bounds
  else: bounds = None
  mask = hsv_mask AND depth_mask       # NEW — was hsv_mask alone
  centroid_cam = centroid(mask)
  return camera_to_base(centroid_cam, extrinsic)
  ↓
workspace.bounds_check(target_base) → ok
  ↓
ik_reach(target_base, frame="ready") → joint_cfg
  ↓
kinematics.analyze_envelope(joint_cfg, duration_ms=hold_time):     # NEW — pre-flight
  if wrist_flex sustained >85% of envelope: raise EnvelopeRiskError("latch_warning ...")
  ↓
trajectory.plan_pick(current, target) → [approach, descend, grasp, lift, retreat]
  ↓
for wp in trajectory:
    motion.replay([wp]) → interpolates
    motion.verify_alive()                                           # NEW — post-motion watchdog
    if not alive: torque_off(remaining); raise LatchError(...)
  ↓
return {status: ok, waypoints_executed: 5, residual_to_target_mm: 3.1}
```

### Flow 3: `robot-md doctor --hardware` (new surface)

```
manifest_checks (existing)
  ↓
hw_checks (NEW):
  feetech.enumerate() → actual_ids
  expected_count = preset.match.drivers.count
  if len(actual_ids) != expected_count: warn("servo count mismatch; possible latch")
  oakd.probe() → rgb_stream_ok, depth_stream_ok
  if not depth_stream_ok: error("depth stream unavailable; depth-aware detectors will fail")
  ↓
extrinsic_check:
  source = manifest.cameras[0].extrinsic_source
  if source == preset_default: warn("run `robot-md calibrate --extrinsic`")
  if source == gripper_silhouette_calibrated: info(f"residual {residual_mm} mm")
```

Three discrete loss points exist in the calibration flow — missing gripper visibility in a pose, servo latch during sweep, residual above tolerance — each with a named recovery path (retry that pose / abort and guide to power-cycle / prompt to accept or redo).

## Error Handling

| Condition | Detection | Response | Actor |
|---|---|---|---|
| **Servo latch during motion** | `verify_alive()` post-motion: missing ID in enumeration | Torque-off remaining servos. Raise `ServoLatchError(servo_id)`. Capability dispatch returns `status: error, reason: servo_latched, servo: wrist_flex, recovery: power_cycle_bus`. Doctor flags on next run. | motion.py, doctor |
| **Trajectory violates envelope** | `analyze_envelope(joint_cfg)`: wrist_flex >85% sustained, or any joint outside `limits_rad` | `KinematicsError(reason=latch_warning, joint=..., angle=...)` before motion. Capability returns `status: unreachable, reason: envelope_risk`. `--force-envelope` allows override (emits loud warning). | kinematics.py, trajectory.py |
| **Gripper-silhouette match fails at a pose** | Cluster too sparse (<5 points within 50mm radius) or too dispersed (std >20mm) | Skip that pose. If ≥4 of 6 poses fail, abort sweep with `CalibrationError(reason=gripper_not_visible)`. Guidance: "check camera mount obstruction; adjust tripod; retry." | gripper_silhouette.py, calibrate_extrinsic.py |
| **Calibration residual too high** | `solve()` residual >15mm mean | Don't write to manifest. Prompt: "residual 22mm — accept, redo, or abort?" Accept requires explicit y. Redo re-runs sweep. | calibrate_extrinsic.py |
| **Depth-aware detector: target inside color mask but outside workspace** | joint mask (color AND depth) empty even though color mask was non-empty | Return `vision_find status: not_found, reason: outside_workspace_depth, hint: "color matched but depth ruled out; check extrinsic or descriptor bounds"` | detectors/hsv.py |
| **Descriptor depth mismatch** | Extrinsic projects workspace → all projected pixels fall outside image | `DetectorConfigError` at descriptor-register time (not at pick time). Fail at init/validate boundary. | detectors/hsv.py, parser |
| **Doctor --hardware on CI (no bus/camera)** | `scan_system` returns empty device list, or bus probe fails | Skip hardware checks, emit info: "no hardware detected; hardware checks skipped." Exit code stays 0 for manifest-only success. | doctor |
| **Init non-interactive without extrinsic cal** | `phase_calibrate_extrinsic` sees `non_interactive=True` | Skip cleanly, `PhaseResult(status=skipped, reason=non_interactive)`. Doctor on that manifest warns `preset_default_extrinsic_uncalibrated`. | phase_calibrate_extrinsic |
| **pick_best tie after count + negative_hints** | Two presets still at same top score (rare after fix) | Return first by name. Log a `ScoringWarning` with all tied candidates. User can override via `--preset`. | init.py |
| **`cv2.aruco` still imported somewhere** | Module-level import leftover | Pre-merge grep check in CI. Removed cleanly as part of hand_eye → calibrate_extrinsic rename. | CI |

### Cross-cutting error principles

- **Fail at the earliest boundary.** Descriptor config errors at parse time, envelope risks at plan time, latch detection at motion-completion time. No silent success that surfaces later as a harder-to-diagnose state.
- **Recovery guidance is structured, not free-text.** Every error emits a `reason` enum + `recovery_hint` string — the MCP surface can programmatically route (`reason: servo_latched` triggers a UI prompt in v0.8, but the field exists now).

## Testing Strategy

### Unit tests (no hardware, run in CI)

- `test_gripper_silhouette.py` — synthetic depth frames. Cases: clean match (high confidence), partial occlusion (medium confidence + centroid drift <5mm), full occlusion (returns None), sparse noise (rejects as cluster-too-sparse).
- `test_calibrate_extrinsic_plan_sweep.py` — given workspace bounds + preset, generates 6 poses all inside envelope, all visible from a synthetic camera at preset-default mount. No duplicate poses. Deterministic (seeded).
- `test_calibrate_extrinsic_solve.py` — fed known (tip_cam, tip_base) pairs with added Gaussian noise, recovers extrinsic within 5mm/1° at noise σ=3mm. Degenerate case (all poses collinear) returns `CalibrationError`.
- `test_hsv_depth_filter.py` — color mask matches both a tabletop object and a wall; workspace-bounds-derived depth filter excludes the wall. With `ignore_workspace_bounds: true`, wall reappears.
- `test_detector_depth_bowl.py` — synthetic bowl + flat-plane depth cloud → bowl returned with correct centroid; bowl-removed → `not_found`.
- `test_kinematics_analyze_envelope.py` — known-safe config returns `ok`; IK output with `wrist_flex=89°` returns `latch_warning`; out-of-limits config returns hard `KinematicsError` (existing behavior preserved).
- `test_motion_verify_alive.py` — mocked bus with full enumeration → `alive=True`; missing one ID → `alive=False, missing=[id]`; verify torque-off called on remaining servos.
- `test_pick_best_count_and_negative_hints.py` — scan with feetech+6 servos + no "leader" string: so_arm101 wins by +5 over so_arm101_leader. Scan with "leader" in any device label: so_arm101_leader wins. Scan with feetech+2 servos (unexpected): so_arm101 stays at base +10 (count mismatch is 0, not negative).
- `test_phase_calibrate_extrinsic_skips.py` — non_interactive, no_camera, no_actuatable_bus, and `extrinsic_source != preset_default` each cause clean skip with correct `PhaseResult.reason`.
- `test_register_overrides_persist.py` — regression for `test_metadata_overrides_persisted_to_manifest`; `--manufacturer "Acme"` reaches the written manifest.

### Integration tests (no hardware, synthetic backend)

- `test_init_calibrate_extrinsic_dry_run.py` — fake TTY + synthetic camera/bus: full init flow including prompted calibration phase. Manifest ends with `extrinsic_source: gripper_silhouette_calibrated` and non-null residual.
- `test_arm_pick_depth_filtered.py` — extend v0.6.1 pick-red-lego integration: add a bogus red pixel at 8m depth, verify pick still targets the real object (not the bogus one).
- `test_doctor_hardware_mode.py` — synthetic bus with missing servo: doctor warns `servo_count_mismatch`. Synthetic camera with no depth stream: doctor errors.

### Hardware tests (opt-in, `RM_HARDWARE=1`)

- `tests/hardware/test_extrinsic_calibrate.py` — run gripper-silhouette sweep on the real arm; assert residual <10mm, extrinsic passes sanity (camera z-axis roughly points at base).
- `tests/hardware/test_pick_red_lego_post_calibrate.py` — end-to-end: `init` → calibrate → pick a real LEGO. Operator visually verifies.
- `tests/hardware/test_latch_recovery.py` — force an over-envelope trajectory behind `--force-envelope`; assert watchdog detects and torques off remaining servos cleanly (no cascade). **Run only with user permission — will latch the servo.**

### Property-based

- `test_extrinsic_roundtrip_property.py` — hypothesis: for any 6-vec in bounded ranges, `matrix_to_six_vec(six_vec_to_matrix(v)) ≈ v`. Already partially covered; extend to cover the `from_mount` cases used in calibrate solver.

### CI matrix

- Unit + integration: every PR, Python 3.11/3.12/3.13 × Linux/macOS.
- Hardware: manual trigger on the dev rig only; not gated on PRs.
- Coverage target: maintain v0.6.3 line coverage; add ~15 new test files, so expected ~3% absolute increase.

### Removed tests (ArUco pathway no longer exists)

- `test_hand_eye.py` (existing v0.6.1 file) → deleted.
- Any `cv2.aruco` fixtures → deleted.

## Release Criteria

v0.7 ships when:

1. All unit + integration tests pass on Python 3.11/3.12/3.13.
2. Coverage maintained or improved vs v0.6.3.
3. `robot-md init` non-interactive run produces valid manifest with no prompts, no surprises.
4. `robot-md init` interactive run on hardware: extrinsic phase runs, residual <10mm, `arm.pick("red_lego")` succeeds on first attempt. **This is the acceptance test that v0.6.3 hardware-proof step 8 was blocked on.**
5. `robot-md doctor --hardware` catches a synthetic servo-latch condition (validated in integration test) and the real one if reproducible on the dev rig.
6. `cv2.aruco` removed from `pyproject.toml`. `opencv-contrib-python` can stay (depthai brings some of it) but is no longer load-bearing for calibration.
7. `test_metadata_overrides_persisted_to_manifest` passes (closes the v0.6.x lingering bug).
8. CHANGELOG entry, version bump (`0.6.3 → 0.7.0`), release notes.

## Backward Compatibility

- **v0.6.3 manifests validate and load unchanged.** All new schema fields are additive and optional: `match.drivers.count` already existed (unused), `match.negative_hints` is new optional, `physics.solver.gripper.silhouette_points` is new optional, `extrinsic_residual_mm` is new optional.
- **Extrinsic calibrated via v0.6.x ArUco still works.** The enum value `hand_eye_calibrated` stays valid; we just no longer produce it as the default. Users on old calibrated manifests don't need to recalibrate.
- **CLI flag rename with deprecation alias.** `robot-md calibrate --hand-eye` prints a deprecation warning pointing to `--extrinsic` but still runs the new flow. Removed entirely in v0.8.
- **Behavior change (intentional):** HSV descriptors now filter by workspace-bounds depth by default. Users whose valid targets sit outside the declared workspace need to add `ignore_workspace_bounds: true` to the descriptor or widen their workspace bounds. This is documented as a **breaking behavior change** in the changelog despite being schema-compatible. Mitigation: doctor warns on this specific new-failure mode with pointer to the fix.
- **v0.5.x manifests:** no additional breakage beyond v0.6.x's inherited breakage (unchanged).

### Migration guidance (goes in CHANGELOG + docs)

- Existing v0.6.x users: re-init or run `robot-md calibrate --extrinsic` to benefit from silhouette calibration; no manifest edits required.
- Users with descriptors matching outside workspace (atypical): add `ignore_workspace_bounds: true` to the affected descriptor OR widen `physics.workspace.bounds_mm`.
- Users calling `--hand-eye` in scripts: update to `--extrinsic` this cycle; deprecation alias removed in v0.8.

### Bump justification

`0.7.0` not `0.6.4` — the HSV default-filter behavior change is user-visible even though schema-compatible, and the calibration flow is a new primary path. Semantic-versioning-wise it's a minor bump (new behavior, back-compat at the schema and data-format level).

## Out-of-Scope for v0.7

Reserved for v0.8 (see `2026-04-20-v0.8-v0.9-roadmap.md`):

- Multi-preset IK (koch_arm, ur5e, franka_panda). Only so_arm101 has a real IK implementation.
- Collision / self-collision checking.
- Grasp planning beyond top-down vertical.
- Cartesian waypoint caching.
- MCP `recent_errors` resource, precondition `suggested_fix` verbosity, `discover` streaming progress.
- Visual servoing, grasp confirmation, force-feedback.
- Multi-camera support (`cameras[1..N]` beyond index 0).

Reserved for v0.9:

- Bimanual / dual-arm coordination.
- Learning-from-demonstration loop.
- Workspace-obstacle SLAM / runtime mapping.
- Mobile-base integration (picar_x, turtlebot4, unitree_go2 actuation).
