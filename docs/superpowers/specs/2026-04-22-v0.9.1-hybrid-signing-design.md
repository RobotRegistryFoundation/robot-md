# robot-md v0.9.1 — hybrid signing + RRF verification (design)

> **Status:** Design. Spans two repos (robot-md + RobotRegistryFoundation). Single combined release.
> **Date:** 2026-04-22
> **Parent:** `docs/superpowers/specs/2026-04-21-v0.9-rcan-3-compliance-design.md` §v0.9.1.
> **Brainstorm decisions:** A (per-RRN keys) / A (sign MintRequest body) / C (auto-mint on unsigned) / C-simplified (strict verify, no grace period — 0 unsigned prod records) / A (single combined release).

## Motivation

robot-md v0.9.0 shipped the schema slot for `compliance.annex_iii_basis` and added rcan-py as a dep, but `register.py` still posts plain-JSON unsigned bodies to RRF, and RRF's `register.ts` treats `pq_signing_pub` / `pq_kid` as pass-through fields without verification. RCAN 3.0 §2.2 requires mandatory ML-DSA-65 + Ed25519 hybrid signatures and rejection of unsigned registrations.

v0.9.1 closes the gap end-to-end: robot-md signs every register; RRF verifies every register and accepts only signed ones. A new PATCH endpoint allows an existing unsigned robot to upgrade to signing without re-minting the RRN.

## Goal

Every robot in the RRF registry is signed with a valid hybrid signature. Client always signs on register; server always verifies.

## Success criteria

All must be true for the v0.9.1 tag:

1. `robot-md register` produces a signed POST body (ML-DSA-65 + Ed25519 hybrid via `rcan.crypto.sign_hybrid`). No `--skip-sign` escape hatch.
2. Keystore file `~/.robot-md/keys/<rrn>.signing.json` (mode 600) persists per-RRN ML-DSA + Ed25519 keypairs.
3. `robot-md` commands against a registered robot with no local `.signing.json` auto-mint a keypair, sign a canonical `{rrn, pq_signing_pub, pq_kid}` payload, and PATCH the RRF record.
4. RRF `POST /v2/robots/register` returns 400 on any body missing `pq_signing_pub` / `pq_kid` / `sig`, and on any body whose signature doesn't verify.
5. RRF `PATCH /v2/robots/[rrn]` accepts `{pq_signing_pub, pq_kid, sig}` bearer-authed via the existing API key; verifies the signature over a canonical `{rrn, pq_signing_pub, pq_kid}` payload; merges the fields into the stored record.
6. RURI `rcan://robotregistryfoundation.org/<slug(manufacturer)>/<slug(model)>/<slug(robot_name)>` is constructed on register when `metadata.ruri` is absent.
7. `cli/tests/test_register.py` is unskipped: 16 stale tests rewritten against current MintRequest/MintResult API + ~10 signing-coverage tests added (~25 total).
8. `cli/tests/test_signing.py` is new (~20 tests): keygen, save/load roundtrip, kid derivation, canonical-JSON determinism, sign/verify, slug rules.
9. Cross-language compat fixture (Python-signed, TypeScript-verified) passes in both repos' CI.

## Client-side (robot-md)

### Keystore

Sibling of existing `~/.robot-md/keys/<rrn>.apikey`. One new file per RRN:

```json
{
  "rrn": "RRN-000000000001",
  "pq_kid": "7c21bf58",
  "ml_dsa": { "pub": "<base64>", "sec": "<base64>" },
  "ed25519": { "pub": "<base64 (32 bytes)>", "sec": "<base64 (32 bytes)>" },
  "created_at": "2026-04-22T12:00:00Z"
}
```

File mode 600 (enforced by signing module, not relied on from umask). No at-rest encryption in v0.9.1 — `700` directory + `600` file is the same guarantee as the existing `.apikey`.

`pq_kid` is the first 8 hex chars of `sha256(ml_dsa_public_key_bytes)`. Matches existing Bob record format (`7c21bf58`).

### Signing module (`cli/src/robot_md/signing.py`)

New file (~180 LoC). Public interface:

```python
@dataclass
class SigningKeypair:
    ml_dsa: rcan.crypto.MlDsaKeyPair
    ed25519_pub: bytes  # 32 bytes, raw
    ed25519_sec: bytes  # 32 bytes, raw
    pq_kid: str         # first 8 hex of sha256(ml_dsa.public_key_bytes)

def generate_keypair() -> SigningKeypair: ...
def save_keypair(rrn: str, kp: SigningKeypair) -> Path: ...   # writes mode 600
def load_keypair(rrn: str) -> SigningKeypair | None: ...
def kid_from_pub(ml_dsa_pub: bytes) -> str: ...
def canonical_json(body: dict) -> bytes: ...                   # json.dumps(body, sort_keys=True, separators=(",", ":")).encode()
def sign_body(kp: SigningKeypair, body: dict) -> dict: ...     # returns body + pq_signing_pub + pq_kid + sig
def verify_body(body: dict) -> bool: ...                        # validates sig in body; used by tests
```

Depends on `rcan.crypto` (ML-DSA) and `cryptography.hazmat.primitives.asymmetric.ed25519` (Ed25519).

`sign_body` appends three fields to the passed dict and returns the result:
- `pq_signing_pub`: base64 ML-DSA public key
- `pq_kid`: kid string
- `sig`: `{"ml_dsa": "<b64>", "ed25519": "<b64>"}`

The `message` signed is `canonical_json(body)` computed **before** the three fields are added. Canonicalization order does not depend on them; adding them after signing is safe because verification also sorts keys on a fresh projection that excludes `sig`.

### register.py changes

`cli_register` rewires:

1. Parse ROBOT.md → build `MintRequest` (existing `_extract_mint_fields`).
2. If manifest has no `metadata.rrn` (fresh register):
   1. `generate_keypair()` + `construct_ruri(manifest)`.
   2. Set `MintRequest.pq_signing_pub` = base64 ML-DSA pub, `pq_kid`, `ruri`.
   3. `body = request.as_body()` (dict form, no sig yet).
   4. `signed = sign_body(kp, body)`.
   5. POST `signed` to RRF `/v2/robots/register`.
   6. Receive RRN.
   7. `save_keypair(rrn, kp)`.
   8. `write_rrn_to_manifest(manifest_path, rrn, record_url)`.
3. If manifest has `metadata.rrn` (existing robot, user ran `register` again):
   - v0.9.1 scope: treat as error ("already registered — use `robot-md rotate-keys` to change keys"). Key rotation is a later release.

New function `auto_mint_if_needed(rrn: str, endpoint: str) -> None`:

1. If `load_keypair(rrn)` returns a value → return (already signed, nothing to do).
2. Else: generate new keypair, canonical-JSON `{rrn, pq_signing_pub, pq_kid}`, sign, PATCH `endpoint/<rrn>` with `Authorization: Bearer <apikey>` + body `{pq_signing_pub, pq_kid, sig}`.
3. On 200: `save_keypair(rrn, kp)`.
4. On 4xx: raise with helpful message; do not save partial state.

`auto_mint_if_needed` is called at the top of `cli_unregister` (currently the only other command that hits RRF). Future commands that touch RRF should call it too.

### Dependency bump

`cli/pyproject.toml`: `"rcan>=3.0,<4.0"` → `"rcan[pq,crypto]>=3.0,<4.0"`. The `[pq]` extra pulls `dilithium-py>=1.0` (ML-DSA primitive). The `[crypto]` extra pulls `cryptography>=42.0` (Ed25519 primitive).

## Server-side (RRF)

### New PATCH + GET endpoint

New file `functions/v2/robots/[rrn]/index.ts`:

```typescript
export const onRequestGet: PagesFunction<Env> = async ({ env, params }) => {
  const rrn = params.rrn as string;
  const val = await env.RRF_KV.get(`robot:${rrn}`, "text");
  if (!val) return err("Not found", 404);
  return ok(JSON.parse(val));
};

export const onRequestPatch: PagesFunction<Env> = async ({ request, env, params }) => {
  const rrn = params.rrn as string;
  const apiKey = extractBearer(request);
  if (!apiKey) return err("Missing bearer token", 401);

  const raw = await env.RRF_KV.get(`robot:${rrn}`, "text");
  if (!raw) return err("Not found", 404);
  const record = JSON.parse(raw);
  if (record.api_key !== apiKey) return err("Unauthorized", 403);

  // v0.9.1 scope: PATCH only upgrades a null -> set transition.
  // Key rotation (replacing an already-set key) is a later release and needs
  // proof-of-possession of the old key.
  if (record.pq_signing_pub) {
    return err("Record already signed; key rotation not supported in v0.9.1", 409);
  }

  const body = await request.json() as {
    pq_signing_pub?: string; pq_kid?: string;
    sig?: { ml_dsa: string; ed25519: string };
  };
  if (!body.pq_signing_pub || !body.pq_kid || !body.sig?.ml_dsa || !body.sig?.ed25519)
    return err("Missing pq_signing_pub / pq_kid / sig", 400);

  const message = canonicalJson({
    rrn, pq_signing_pub: body.pq_signing_pub, pq_kid: body.pq_kid,
  });
  const verified = await verifyHybrid(body.pq_signing_pub, body.sig, message);
  if (!verified) return err("Signature verification failed", 400);

  record.pq_signing_pub = body.pq_signing_pub;
  record.pq_kid = body.pq_kid;
  record.updated_at = new Date().toISOString();
  await env.RRF_KV.put(`robot:${rrn}`, JSON.stringify(record));
  return ok(record);
};
```

### Tightened register.ts

`onRequestPost` in `functions/v2/robots/register.ts` grows a verify step:

```typescript
const { name, manufacturer, model, firmware_version, rcan_version,
        pq_signing_pub, pq_kid, ruri, owner_uid, sig } = body;

if (!pq_signing_pub || !pq_kid || !sig?.ml_dsa || !sig?.ed25519) {

  pq_signing_pub, pq_kid,

```

### Shared verify helper (`functions/_lib/verify.ts`)

New file (~80 LoC):

```typescript
import { ml_dsa65 } from "@noble/post-quantum/ml-dsa";

export function canonicalJson(obj: Record<string, unknown>): Uint8Array {
  return new TextEncoder().encode(JSON.stringify(sortKeys(obj)));
}

export async function verifyHybrid(
  ml_dsa_pub_b64: string,
  sig: { ml_dsa: string; ed25519: string; ed25519_pub?: string },
  message: Uint8Array,
): Promise<boolean> {
  // ML-DSA-65 via @noble/post-quantum
  const mlDsaOk = ml_dsa65.verify(
    b64ToBytes(ml_dsa_pub_b64),
    message,
    b64ToBytes(sig.ml_dsa),
  );
  // Ed25519 via WebCrypto
  const edPub = b64ToBytes(sig.ed25519_pub ?? /* derived from record */);
  const edOk = await crypto.subtle.verify("Ed25519",
    await crypto.subtle.importKey("raw", edPub, { name: "Ed25519" }, false, ["verify"]),
    b64ToBytes(sig.ed25519),
    message);
  return mlDsaOk && edOk;
}
```

**Ed25519 public key source.** The MintRequest body includes `pq_signing_pub` (ML-DSA) but not Ed25519 pub directly. The client attaches `sig.ed25519_pub` as a sibling of `sig.ed25519` in the hybrid sig. RRF reads both from the request. On PATCH, same applies.

## Risks

1. **ML-DSA JS ↔ Python parameter compat.** Both sides must use ML-DSA-65 (FIPS 204) exactly. *Mitigation:* cross-language fixture test in CI (§ Cross-language compatibility test above). If `@noble/post-quantum`'s `ml_dsa65.verify` rejects a Python-signed message, we block shipping until reconciled.
2. **Ed25519 encoding friction.** rcan-py returns raw 32-byte keys; WebCrypto expects `crypto.subtle.importKey("raw", ...)`. `@noble/curves` accepts raw bytes too. *Mitigation:* keystore stores raw bytes base64-encoded; import paths documented in signing.py and verify.ts.
3. **Canonical JSON drift.** Python `json.dumps(sort_keys=True, separators=(",", ":"))` vs TypeScript `JSON.stringify(sortKeys(obj))`. Edge cases: non-ASCII in manufacturer names, floats (none here — all string/int), null handling. *Mitigation:* fixture test covers the exact register body shape; keep MintRequest's `as_body` to str/int/bool-only.
4. **PATCH race on same RRN.** Two concurrent commands auto-minting for the same unsigned robot. *Mitigation:* server returns 409 Conflict if `record.pq_signing_pub` is already set with a different key at write time. Low probability; accept for v0.9.1.
5. **robot-md's own `examples/bob.ROBOT.md` stale RRN.** The file references `RRN-000000000003` which was purged. *Mitigation:* one-line cleanup commit clears `metadata.rrn` so fresh-clone users can run `robot-md register` without the "already registered" error path.
6. **Cloudflare Workers bundle size.** `@noble/post-quantum` ML-DSA is sizable (~100 KB minified). *Mitigation:* Workers limit is 1 MB compressed; well within. Cold-start cost negligible.

## Out of scope (deferred)

- Key rotation with proof-of-old-key (user wanting to replace compromised keys). Needs `PATCH /v2/robots/[rrn]` to require a signature by the *old* key when `pq_signing_pub` is already set — more delicate. Separate release.
- At-rest encryption of `<rrn>.signing.json`. Current file-mode-600 protection matches `.apikey`; tighter storage (keychain, `sops`) is separate hardening.
- §22 FRIA enforcement (`annex_iii_basis` → require `fria_ref`). v0.9.2.
- §23-§26 external artifact CLI. v0.9.3-v0.9.5.
- RCN/RMN/RHN registry IDs. v0.9.6.
