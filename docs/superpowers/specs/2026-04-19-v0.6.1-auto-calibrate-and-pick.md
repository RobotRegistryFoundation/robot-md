# v0.6.1 — Auto-calibrate + `arm.pick(target)` end-to-end

**Date:** 2026-04-19
**Status:** draft
**Goal:** After `robot-md init`, the operator can invoke `arm.pick("red_lego")` / `arm.place("white_bowl")` as a single agent turn — no `pose teach`, no calibration, no manual steps. The v0.6.0 descriptive layer becomes a prescriptive, actuatable layer.
**Target robot:** SO-ARM101 + OAK-D. Multi-preset extension deferred to v0.7.

---

## Background

v0.6.0 closed 10 of the 10 spec gaps identified in the 2026-04-19 gap analysis: named poses, capability contracts, object descriptors, learned skills, MCP discovery verbs, preconditions, cross-surface parity. But the pick-red-lego-to-bowl loop still requires:

1. An operator `pose teach ready` interaction
2. A hand-eye calibration run
3. `arm.pick(target)` is a stub that ignores its argument

v0.6.1 closes this last mile. The design posture is **zero friction first, optional precision later** — ship preset defaults that work, make calibration an opt-in command for users who want to reduce residual error.

---

## Architecture

Four pieces, all SO-ARM101 only for this milestone:

1. **Auto-calibrate `ready` pose at init** — existing `Kinematics.ik_reach` already solves from DH params. `init` feeds it a canonical target (200mm forward, 0 lateral, 50mm above base) and writes the resulting joint angles to `physics.poses.ready`. Stateless, no hardware, runs in <50ms. Replaces the manual `pose teach` for the common case.

2. **Default extrinsic in preset** — `so_arm101.yaml` ships a pre-measured 4x4 camera→base matrix (OAK-D on tripod at canonical mount position). `init` writes it into `physics.cameras[0].extrinsic`. Accuracy ~2-3cm — sufficient for LEGO-sized picks.

3. **`arm.pick(target)` wired end-to-end** — backend flow: target descriptor → `vision.find` (camera XYZ) → extrinsic matmul (base XYZ) → workspace bounds check → IK for approach pose (above target by `approach_height_mm`) → joint-space interp to approach → cartesian linear descent (multi-slice IK) → close gripper → joint-space lift to approach → return. `arm.place(target)` mirrors with a bowl descriptor and gripper-open at the bottom.

4. **Opt-in `robot-md calibrate --hand-eye`** — ArUco marker, ~8 sampled poses, `cv2.calibrateHandEye`, overwrites extrinsic for users who want precision beyond the shipped default. Ships a PDF marker in package assets.

Data flow at pick time:

```
arm.pick("red_lego")
  → detectors.hsv(frame) → (u, v, depth_mm)
  → pinhole back-project via K → (x, y, z) in camera frame
  → extrinsic_4x4 @ point → (x, y, z) in base frame
  → workspace bounds check (abort if outside)
  → kinematics.ik_reach(target) → joint angles for approach
  → trajectory.plan_pick → ordered waypoints
  → motion.execute_waypoints → bus writes
  → status: ok | unreachable | no_target | blocked | error
```

## Components

### New files

- `cli/src/robot_md/auto_calibrate.py` — `compute_ready_pose(spec, target_mm=(200, 0, 50))` returns `dict[str, int]` of joint_id → step count. Uses `kinematics.ik_reach` then `angles_to_step_targets`. Pure function, no I/O. Returns `None` if IK unreachable, surfacing the reason for diagnostics.
- `cli/src/robot_md/init_phases/auto_calibrate_ready.py` — init phase that calls `compute_ready_pose` and writes to `physics.poses.ready`. Inserted **before** `teach_poses` phase. Skipped if `poses.ready` already exists (user override respected). Skipped if `physics.solver.ik_provider` is null or unrecognized (preset doesn't support auto-calibrate — logs a note). Skipped if IK returns unreachable (surfaces a doctor warning).
- `cli/src/robot_md/extrinsic.py` — pure functions:
  - `camera_to_base(point_cam_mm: tuple[float, float, float], extrinsic_4x4) -> tuple[float, float, float]`
  - `identity_extrinsic() -> np.ndarray`
  - `from_mount(position_mm: tuple, look_at_mm: tuple, up=(0,0,1)) -> np.ndarray` — builds a camera→base 4x4 from human-readable mount description, so presets can be authored without hand-computing matrices.
- `cli/src/robot_md/trajectory.py` — `plan_pick(start_joints, target_base_xyz, approach_height_mm, kin, slices=5) -> list[Waypoint]`. Hybrid plan: one joint-space waypoint at approach height, N cartesian-linear descent slices to grasp, gripper close, one joint-space lift waypoint. `plan_place` mirrors with gripper open at bottom. Each `Waypoint` is `{joints: dict[str, int], gripper_steps: int | None, settle_ms: int}`. Pure function.
- `cli/src/robot_md/hand_eye.py` — `calibrate(bus, camera, poses_deg: list[dict], marker_id: int, marker_size_mm: float) -> np.ndarray`. Wraps `cv2.aruco.detectMarkers` + `cv2.calibrateHandEye`. Opt-in, gated behind the CLI flag.
- `cli/src/robot_md/assets/aruco_marker_50mm.pdf` — 50mm DICT_4X4_50 marker, id=0. Ships with the package; user prints + tapes.

## Default extrinsic: shipped assumption

The `so-arm101` preset's default extrinsic assumes a specific physical setup — if the user mounts differently, pick will miss by the mount error. Tradeoff: zero user action vs. accuracy dependent on setup matching the default.

**Shipped assumption (SO-ARM101 + OAK-D canonical):**

- OAK-D tripod centered on arm base in Y (camera directly in front of arm).
- Camera 400mm in front of arm base (+X).
- Camera 300mm above tabletop (+Z).
- Camera pitched 30° down (looking at tabletop centered ~200mm in front of arm).
- Derived 4x4 matrix shipped in `so_arm101.yaml`.

**Trust model:**

- `init` writes this default with a YAML comment: `# default extrinsic assumes OAK-D tripod at (400, 0, 300)mm from arm base, pitched 30° down. Run 'robot-md calibrate --hand-eye' if your mount differs.`
- Manifest records `physics.cameras[0].extrinsic_source: preset_default`. After hand-eye runs, flips to `hand_eye_calibrated`.
- `doctor` warns (not errors) when `extrinsic_source == preset_default`: "camera pose is a preset guess — run hand-eye calibration for production accuracy".
- `arm.pick` does NOT block on `extrinsic_source` value — it trusts whatever extrinsic is declared. Safety comes from workspace bounds: if IK target lands outside `physics.workspace.bounds_mm`, abort before motion.

**Why this works for LEGOs:** A 2cm extrinsic error plus a 15mm-wide gripper still closes on a 15mm LEGO if the gripper descends vertically and the target is in XY ballpark. Workspace bounds prevent catastrophic misses.

## Error handling

Failure modes and responses:

| Case | Status | Reason | Motion? |
|---|---|---|---|
| Target descriptor not declared in `vision.object_descriptors` | blocked | descriptor_not_declared | no |
| Vision finds no match (empty detection) | no_target | `<descriptor_id>_not_visible` | no |
| Target outside `physics.workspace.bounds_mm` | unreachable | outside_workspace | no |
| `kinematics.ik_reach` raises `KinematicsError` | unreachable | ik_failed | no |
| Extrinsic is null despite precondition checks | blocked | extrinsic_missing | no |
| Bus read/write fails mid-trajectory | error | bus_error | halt + torque hold |
| `estop` set | blocked | estop | no |

Dry-run: `execute_capability(..., dry_run=True)` runs the full resolution + IK + waypoint plan, returns the planned waypoints as structured JSON, never writes to bus. Existing v0.6.0 dry-run path in `execute_capability.py` covers this — we just extend the return payload to include waypoint previews.

HITL gating: `arm.pick` / `arm.place` land in the `manipulate` scope. Preset does **not** declare `manipulate` in `safety.hitl_gates` by default — preconditions + workspace bounds are sufficient safety for LEGO-scale pick. Users who want auth-gated pick add a `manipulate` HITL gate themselves.

## Dependencies

- `opencv-python` and `opencv-contrib-python` — ArUco detection lives in `cv2.aruco`, part of `opencv-contrib`. Verify `pyproject.toml` pins `opencv-contrib-python` (depthai brings in `opencv-python` but not necessarily contrib). If not, add to `cli/pyproject.toml` dependencies.
- `numpy` — already a transitive dep; used directly for extrinsic math.
- No new system-level deps. Hand-eye works on any machine that can already run the perception stack.

## Backward compatibility

- All new fields (`extrinsic_source`, new `ik_provider` enum value) are optional or additive. v0.6.0 manifests validate cleanly under v0.6.1.
- v0.6.0 `poses.ready` (if already present, e.g., via `pose teach`) takes precedence over auto-calibrate. No silent overwrite.
- Users on v0.6.0 can upgrade to v0.6.1 and existing manifests keep working. `arm.pick` becomes functional only after a re-init (which rewrites extrinsic from preset) or manual extrinsic write.

## Release criteria

v0.6.1 ships when:

1. All unit tests pass.
2. Integration dry-run `arm.pick("red_lego")` succeeds end-to-end on the CI matrix (no hardware).
3. Hardware test `test_pick_red_lego.py` succeeds at least once on a real SO-ARM101 + OAK-D with the preset-default extrinsic (no hand-eye calibration).
4. `robot-md init` on a fresh workspace produces a manifest where `validate` passes AND `physics.poses.ready` is populated AND `physics.cameras[0].extrinsic` is non-null.
5. Changelog entry and version bump (`0.6.0 → 0.6.1`).

## Out of scope (deferred to v0.7+)

- Multi-preset IK (only SO-ARM101 for now).
- Collision checking / self-collision avoidance (workspace bounds is the safety envelope).
- Grasp planning beyond top-down vertical.
- Visual servoing / closed-loop refinement during descent.
- Cartesian waypoint caching for repeat picks.
- Dynamic extrinsic refinement (gripper-as-fiducial auto-calibration).
